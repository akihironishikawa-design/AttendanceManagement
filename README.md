# 勤怠突合 PoC (Windows デスクトップアプリ)

高根カントリー倶楽部様 勤怠締め処理支援システム — シフト表と打刻データの突合 PoC

**C# / .NET 8 / WPF / NPOI 2.8.0** · 作成日 2026-08-12

---

## 1. このPoCで何ができるか

| できること | 内容 |
|---|---|
| シフト表の読込 | `.xls` の任意シートを選択して 1人1日に展開 |
| 打刻データの読込 | タイムレコーダー出力の「出席記録」シートを読込。`06:4917:07` のような連結表記から時刻を抽出 |
| 社員名の解決 | 空白の表記ゆれは自動解決。役職表記(例「平山 部長」)は別名マスタで対応 |
| 突合 | 「正規化社員名 + 日付」で完全一致突合 |
| 判定 | 遅刻・早退・打刻漏れ・公休打刻・シフトなし打刻・早出30分・時間外30分 など 21 コード |
| 勤務時間 | 打刻を15分単位に丸め、拘束時間の長さから休憩を自動計算(6h以内15分 / 8h未満45分 / それ以上1.5h) |
| 画面表示 | 判定の重大度で色分けした一覧。要確認のみ表示・氏名/部門/判定での絞り込み |
| 矛盾の確認・修正 | シフト表をベースに1社員1行で表示し、同じセルに打刻を重ねる。矛盾のある日は背景色とコメントで理由を表示。画面で直すと判定はその場で再計算 |
| マスタの保守 | 社員名の別名・勤務区分・勤務パターンを画面で追加・修正・削除。XMLを直接編集する必要はありません |
| 作業の保留 | 編集の途中で決まった1ファイル(`作業データ\勤怠突合状況.xlsx`)に保存し、次回そこから続きを編集。判定は開いたときのマスタで計算し直します |
| Excel出力 | 業務フロー STEP1 の4帳票(出席記録レポート / 申請書 確認一覧 / 出勤簿 / パート給与計算表)。既存様式のレイアウト・数式・印刷設定を維持したまま値を書き込み |

## 2. 実サンプルでの検証結果

お預かりした実ファイルで動作確認済み(2026-08-12 実施)。

**入力**
- シフト表 : `2026 営業課・競技課シフト(原本行事）表.xls` シート `7月修正`
- 打刻データ : `[インポート]タイムレコーダーデータ.xls` シート `出席記録`
- テンプレート : `[提出]出席記録レポート.xlsx`

**読み取り結果(レイアウトは自動検出)**

```
[打刻]   日番号行=4行目  日列=A〜G(7日分)   社員数=74  ブロック=2行構成
[シフト] 日番号行=31行目 日列=G〜AK(31日分) 氏名列=D   社員数=14
対象年月 = 2026年7月 (ファイルから自動判定)
処理時間 = 約 0.3 秒
```

**突合・判定(「シフト表に載っている社員のみ」で実行)**

| 区分 | 件数 | 主な内訳 |
|---|---:|---|
| 正常 | 194 | 公休 172 / 正常 10 / 有給 8 / 欠勤 4 |
| 参考 | 2 | 出張 2 |
| 警告 | 16 | 時間外30分以上 18 / 早出30分以上 1 |
| 要確認 | 191 | 両打刻なし 168 / 早退候補 16 / 遅刻候補 3 / 打刻が1件のみ 3 / 公休に打刻あり 2 |
| エラー | 31 | 氏名未解決 31 (「宮崎 プロ」1名分) |

**帳票出力**

```
出力社員数 : 14 名 (シフト表の記載順)
書込セル数 : シフト 200 / 打刻 225
```

生成した `.xlsx` を Excel でレンダリングし、罫線・土日の網掛け・列幅・結合セル・
印刷設定(A4横 / 横1ページ / 1〜5行目を各ページの見出しに繰り返し)を確認済み。

### 検証で分かったこと(要ご確認)

1. **「両打刻なし」168件は打刻データの期間が短いため**
   サンプルの打刻データは 7/1〜7/7 の1週間分でしたが、シフトは31日分あります。
   月次の締めでは 1か月分を出力した打刻データが必要です。アプリはこの食い違いを検出して
   処理ログに注意を表示します。

2. **氏名の役職表記は別名マスタが必須(Blocker B-08)**
   シフト表は「平山 部長」「原田 課長」「野澤 係長」「久保 プロ」「宮崎 プロ」と
   役職で書かれており、打刻データの氏名と一致しません。
   `masters/name_alias.xml` に4件を候補として登録済みですが、**お客様の承認が必要**です。
   「宮崎 プロ」は打刻データに同姓が3名(宮崎 由佳・宮崎 玲子・宮崎 隆)いるため
   機械的に特定できず、意図的に未解決のままにしています。

3. **予定終了時刻がシフト表に無い(Blocker B-03)**
   早退・時間外の判定には予定終了時刻が必要ですが、シフト表には開始時刻しかありません。
   `masters/work_pattern.xml` に**暫定の所定8時間**を入れて動作させています。
   実際の勤務パターンと休憩ルール(Blocker B-04)の確定が必要です。

4. **帳票の書式はテンプレートから複製せず、アプリ側で作る**
   お客様の実ファイルを元にしたテンプレートには、条件付き書式の名残(緑・灰の塗り、斜線)や
   社員ごとにばらついた罫線が残っていました。それを複製すると出力にもばらつきが出るため、
   テンプレートからは**表題・期間欄・用紙設定・列幅**だけを引き継ぎ、
   日番号行から下(罫線・塗り・フォント)は毎回アプリ側の書式で作り直します。
   テンプレートは `.xlsx` 形式である必要があります。

## 3. ビルドと実行

### 必要なもの
- Windows 10/11
- .NET 8 SDK (または Visual Studio 2022 17.8 以降)

### セットアップ(clone した直後に一度だけ)

**実在の社員名を含むマスタ2つはリポジトリに入っていません。** 見本を複製してください。

```powershell
Copy-Item masters\employee.sample.xml   masters\employee.xml
Copy-Item masters\name_alias.sample.xml masters\name_alias.xml
```

見本は架空の氏名です。実運用のマスタは、お客様の「従業員データ.xlsx」から
`import-employees` で作るか、画面の「マスタを編集」で入力してください。
この2ファイルが無くても起動はしますが、全員が正社員として扱われ、氏名の別名解決も効きません。

同じ理由で、お客様の実データ(`Materials\` `sample\` `doc\` と出力結果の xlsx)も
リポジトリには含めていません。

### 手順

```powershell
# ビルド
dotnet build TakaneAttendance.sln -c Release

# アプリの起動
.\run.ps1

# 実行ファイルを配布用に発行(単一フォルダ)
dotnet publish src\TakaneAttendance.Wpf -c Release -r win-x64 --self-contained false -o publish
```

> **`dotnet run` は直接使えません。**
> ソリューション直下には実行できるプロジェクトが Wpf と Cli の2つあるため、
> 引数なしの `dotnet run` は「実行するプロジェクトが見つかりませんでした」で失敗します。
> `.\run.ps1` を使うか、`dotnet run --project src\TakaneAttendance.Wpf` のように対象を指定してください。

| コマンド | 内容 |
|---|---|
| `.\run.ps1` | WPF 画面を Debug で起動 |
| `.\run.ps1 -Release` | Release で起動 |
| `.\run.ps1 -Cli <引数...>` | 確認用コンソールを実行(引数はそのまま渡される) |

VS Code では **F5** で起動できます(`.vscode\launch.json`)。
「勤怠突合 PoC (WPF)」と「確認用コンソール (CLI・サンプルで突合)」の2構成を用意しています。
`Ctrl+Shift+B` でソリューションのビルド、タスク一覧から `run` / `publish` も実行できます。

`publish\勤怠突合PoC.exe` を実行してください。
`masters\` と `templates\` は実行ファイルと同じ階層に配置されます。

### 画面の使い方

画面は上部の **3ステップ**(1. データ取込 / 2. 突合・確認・修正 / 3. 帳票出力)で進みます。
クリックすると行き来できます。

**1. データ取込**

1. **シフト表**を選択 → シートを選ぶ(「修正」を含むシートが自動選択されます)
2. **打刻データ**を選択 → 「出席記録」シートが自動選択されます
3. **突合実行**

   ※ **画面へのドラッグ＆ドロップ**でも指定できます。
     画面のどこに落としても、ファイルの中身を見て シフト表 / 打刻データ / 帳票テンプレート に
     自動で振り分けます(複数まとめて落とすことも可能)。
     入力欄の上に直接落とした場合は、判別によらずその欄に入ります。
     一時保存ファイルを落とした場合は「保留を開く」として扱います。

> **取込画面に帳票テンプレートの欄はありません。**
> 突合そのものにテンプレートは要らず(作業番号・部門は従業員マスタから補完します)、
> テンプレートは **「3. 帳票出力」タブで帳票ごとに指定**します。

**2. 突合・確認・修正**

4. 「出席記録レポート(編集可)」タブで、提出する帳票と同じ形のまま内容を確認・修正
   (途中でやめる場合は **「保留(作業途中を保存)」**。次回は **「保留を開く」** で続きから)
5. 「突合結果」タブで差異を一覧で確認(既定では正常以外のみ表示)
6. 「氏名未解決」タブに氏名が出た場合は、行を選んで **マスタに登録**(正式氏名を選ぶだけ)

**3. 帳票出力**

7. 出力する帳票をチェックし、**テンプレートが要る帳票はここでファイルを指定**します
8. 出力先フォルダを選び、**「選択した帳票を出力」**
   → `年月_日時` のサブフォルダに帳票と実行ログが出て、フォルダが自動で開きます

### 「出席記録レポート(編集可)」タブ

**シフト表を土台に、打刻データを重ねて矛盾を見る画面**です。

- **①シフト表がベース** — 社員一覧・並び順・部門はシフト表の記載どおり。**1社員 = 1行**
- **②打刻をマージ** — 同じセルの中に予定と実績を重ねる
- **③矛盾を色分け** — 突合の判定が付いた日は背景色が変わり、セルにカーソルを合わせると理由が出る

左端に社員情報の列(固定表示)、その右に対象月の日列(1〜末日、曜日つき・土日は網掛け)。
**社員情報も日セルも、同じ3段構成**にして段の高さを揃えています。

```
  佐藤 一郎       7:30   ← 1段目: 氏名     / シフト(予定) 勤務区分「公」や予定開始時刻。青字
  9001           07:22   ← 2段目: 作業番号 / 出勤打刻
  競技課         15:32   ← 3段目: 部門     / 退勤打刻
```

氏名・作業番号・部門は、セルをダブルクリックするとその場で修正できます(3段とも入力欄になります)。

| 背景色 | 意味 | 例 |
|---|---|---|
| 赤系 | エラー | 氏名未解決 |
| 橙系 | 要確認 | 両打刻なし / 遅刻候補 / 早退候補 / 公休に打刻あり |
| 紫系 | 警告 | 早出30分以上 / 時間外30分以上 |
| 青灰 | 参考 | 出張 / 予定終了時刻が未登録 |
| 色なし | 矛盾なし | 正常 / 公休 / 有給 |

ツールチップには「日付・氏名・シフト・打刻・判定」が出ます。

| 操作 | 内容 |
|---|---|
| セルの編集 | 日付のセルをダブルクリック(または Enter / F2)で編集ポップアップを開く |
| セルを空欄にする | Delete または BackSpace |
| 絞り込み | 氏名・部門・作業番号で絞り込み |
| 保留(作業途中を保存) | 編集中の内容を `作業データ\勤怠突合状況.xlsx` に保存する(保存先は聞きません) |
| 保留を開く | `作業データ\勤怠突合状況.xlsx` を読み込み、続きから編集する |
| 編集内容を元に戻す | 画面の編集を破棄し、突合結果の内容に戻す |

編集したセルは**左端に橙色の帯**が付き、**判定はその場で計算し直します**(突合と同じ判定ルールを通すため、
突合直後の判定と食い違いません)。打刻漏れの補記や勤務区分の訂正を、Excel を開かずにこの画面で済ませてから
出力できます。編集内容は元のシフト表・打刻データを変更しません。
再度「突合実行」を押すと編集は破棄されます(保留していない編集がある場合は確認します)。

### 作業の保留(中断して、続きから再開する)

1か月分の確認は一度で終わらないため、**編集の途中で保存して、後日そこから再開**できます。

| 操作 | 内容 |
|---|---|
| 保留する | 「出席記録レポート(編集可)」タブの **「保留(作業途中を保存)」** を押す |
| 再開する | **「保留を開く」** を押す |

> **保存先は聞きません。決まった1ファイルに上書きします。**
> 締めの作業中は何度も保存するため、保存のたびにダイアログを出さない作りにしています。
>
> ```
> 実行ファイルと同じ階層\作業データ\勤怠突合状況.xlsx
> ```
>
> 上書き前の内容は同じ場所に `勤怠突合状況.xlsx.bak` として1世代だけ残ります。

一時保存ファイルは **Excel 形式**(仕様書 v3.0 第8.4章)で、3つのシートに分かれています。

| シート | 内容 |
|---|---|
| 入力条件 | 取り込んだファイル・シート名・対象年月・絞り込み設定・**入力原本のハッシュ** |
| 帳票 | 社員ごとに シフト / 打刻 / 予定終了 / 備考 / 編集 の5行 × 日列 |
| 修正履歴 | 修正ID・日時・修正者・前後の値・判定の変化・備考 |

- **画面の内容がそのまま入ります** — 社員一覧・シフト・打刻・編集した箇所に加え、
  **帳票には出力しない予定終了時刻**も保持します。これが無いと早退・時間外を判定し直せません
- **判定は開いたときに計算し直します** — 保留中にマスタを直した場合、その内容が反映された
  状態で再開できます。保留時と判定が変わったセル数は処理ログに出ます
- **入力原本の差し替えを検証します** — 保存時のハッシュと突き合わせ、シフト表・打刻データが
  差し替わっている場合は処理ログで知らせます
- 保留していない編集があるまま **突合実行・保留を開く・アプリを閉じる** を行うと確認が出ます
- 従来の `.kintai.json` を画面にドラッグ＆ドロップすると、そのファイルからも再開できます

> **別の月の作業が入っている場合だけ確認します。**
> 一時保存ファイルは1つのため、7月の作業が入っているときに8月を保留しようとすると
> 上書きしてよいか尋ねます(`.bak` には上書き前の内容が残ります)。

> **「保留を開く」を押すと、そのまま突合まで済ませます。**
> 一時保存ファイルに入っているのは編集中の帳票だけのため、開いただけでは
> 「突合結果」「氏名未解決」タブと上部の件数、「3. 帳票出力」タブが空のままになります。
> そこで、保留したときのシフト表・打刻データを読み直して突合し、
> **保留していた編集をその結果に重ねます**。締めの続きをそのまま行えます。
>
> | 重ねるもの | 重ねないもの |
> |---|---|
> | 画面で直したシフト・予定終了時刻・備考・修正履歴 | 打刻(タイムレコーダーの原値のため編集できません) |
>
> 重ねた件数は処理ログに出ます。元ファイルが差し替わっていた場合は**新しい内容に編集が重なり**、
> 編集していた社員が居なくなっていた場合はその氏名を処理ログで知らせます。

> **元のシフト表・打刻データが見つからない場合は、帳票だけを戻します。**
> ファイルを移動・削除した後でも編集内容は失われません。処理ログにその旨が出ます
> (この状態でファイルを指定して「突合実行」を押すと、編集は破棄されます)。

> **予定開始時刻は画面だけの表示です。**
> 現行の提出帳票のシフト行には勤務区分の文字値しか載らないため、`7:30` のような予定開始時刻は
> 出力しません(件数は処理ログに出ます)。矛盾を目で確認するために画面には表示しています。

#### 編集ポップアップ

対象セルのすぐ下に開き、その日のシフト(予定)と打刻(実績)をまとめて直せます。
見出しに現在の値と判定内容が出ます。

| 入力 | 内容 |
|---|---|
| シフト:勤務区分 | `masters\shift_type.xml` の一覧から選択(公=公休 / 有=有給 / 欠=欠勤 / 半=半休 / 出張 / 本部勤務)。マスタは突合実行のたびに読み直します |
| シフト:開始時刻 | 通常勤務の日はこちら。勤務区分とはどちらか一方を使います |
| 打刻:出勤 / 退勤 | **時と分をそれぞれ一覧から選択**(分は5分刻み)。片方だけの入力も可能 |
| 空にする | その日のシフト・打刻をどちらも空欄にして閉じる |

時刻はドロップダウンから選ぶだけで入力できます。分の一覧は5分刻みですが、
`47` のように一覧に無い値は欄に直接入力できます(時の欄に `0730` とまとめて入れても可)。
既存の値を開いたときは、その時刻がそのまま欄に入った状態で開きます。

確定すると帳票へ出力する原文の形に組み立て直します。
打刻はタイムレコーダー出力に合わせて `06:0015:00`(時が2桁)、
シフトはシフト表に合わせて `6:00`(時が1桁)になります。

勤務区分マスタに無い値がすでにセルに入っている場合は、その値も一覧の先頭に出るため、
ポップアップで開いても値を失いません。

### 出席記録レポートの出力

画面に表示されている内容が、そのまま `.xlsx` になります。

- **警告・要確認・エラーの日は、判定内容をセルのメモとして残します**。
  打刻セルにポインタを合わせると、画面のセルと同じ内容(日付・氏名・判定・シフト・打刻)が出ます。
  正常・参考の日には付けません(数が多く、見たい判定が埋もれるため)
- 出力後に**「Excel で開きますか?」**と確認します。「はい」で出力したブックが開きます

### 勤務時間と休憩の自動計算 (統合仕様書 v3.0 第14章)

パート・アルバイト給与計算表のための計算です。打刻を**15分単位に丸めてから**、
拘束時間(丸めた退勤 − 丸めた出勤)の長さで休憩時間を決めます。
**実労働時間 = 拘束時間 − 休憩時間**です。

一覧画面・出席記録レポート・遅刻早退の判定には、**丸めない実打刻**を使います(仕様書 14.1)。

丸めは**出勤=切り上げ / 退勤=切り捨て**です。15分の区切りに達するまでは勤務時間に入りません。

```
6:50 出勤 → 7:00 として計算      15:14 退勤 → 15:00 として計算
7:01 出勤 → 7:15 として計算      14:59 退勤 → 14:45 として計算
```

> **丸めの方向は未確定です(仕様書 要確認 Q-01)。**
> 上記は暫定値で、`mastersreak_rule.xml` の `inRounding` / `outRounding` を
> 書き換えるだけで切り上げ・切り捨て・四捨五入に切り替えられます。

| 丸め後拘束時間 | 休憩 | 境界例 |
|---|---|---|
| 6時間以内 | 15分 | `6:00` → 15分 |
| 6時間超〜8時間以内 | 45分 | `6:15` → 45分 / `8:00` → 45分 |
| 8時間超 | 1時間30分 | `8:15` → 90分 |

設定は `mastersreak_rule.xml` です。**帯・丸めの単位・丸めの方向をすべて変更できます。**

```xml
<breakRule unitMinutes="15" inRounding="up" outRounding="down">
  <band upToHours="6" breakMinutes="15"/>   <!-- 6時間以内 -->
  <band upToHours="8" breakMinutes="45"/>   <!-- 6時間超〜8時間以内 -->
  <band               breakMinutes="90"/>   <!-- 8時間超 -->
</breakRule>
```

- `inRounding` / `outRounding` … `up`(切り上げ) / `down`(切り捨て) / `nearest`(四捨五入)
- `upToHours` は**以内**(境界を含む)、`underHours` は**未満**(境界を含まない)
- 上から順に見て、最初に当てはまった行の `breakMinutes` を使います

確認用コンソールで、打刻を渡して結果を確かめられます。

```powershell
.
un.ps1 -Cli breaktime
.
un.ps1 -Cli breaktime 7:07 15:08  7:00 14:52
```

### 判定ルール (統合仕様書 v3.0 第13章)

評価は**勤務区分 → 打刻件数 → 時刻判定**の順に行います。1日に複数の判定コードを保持し、
画面には**優先順位で1つに絞った主判定**を表示します。

```
要確認 ＞ 遅刻 ＞ 早退 ＞ 早出 ＞ 時間外 ＞ 正常
```

| 判定 | 条件 | 備考 |
|---|---|---|
| 遅刻 | 実打刻1回目 > 予定開始 | 1分超過から対象 |
| 早出 | 実打刻1回目 ≦ 予定開始 − 30分 | 29分は対象外、30分は対象 |
| 早退(正社員) | 最終打刻 < 予定開始 + **9時間30分** | 拘束時間の基準。休憩1.5時間を含む |
| 早退(パート等) | 最終打刻 < 予定終了 | 予定終了が未登録の日は判定しない |
| 時間外 | 最終打刻 ≧ 予定終了 + 30分 | |

打刻件数による判定は次のとおりです(仕様書 第12章)。

| 打刻件数 | 通常勤務 | 出張 |
|---|---|---|
| 0 件 | 打刻漏れ | 終日出張(正常・申請書確認) |
| 1 件 | 打刻漏れ | 打刻漏れ(半日出張候補) |
| 2 件 | 時刻判定へ | **半日出張**(正常・遅刻早退を判定しない) |
| 3 件以上 | **要確認**(最初と最後で時刻判定を続行) | 要確認 |

**しきい値は `masters\judgement_rule.xml`** で変更できます
(早出30分 / 時間外30分 / 正社員拘束9時間30分 / 遅刻早退の許容0分)。

**雇用区分は `masters\employee.xml`(従業員マスタ)** で決まります。
登録が無い社員は正社員として扱い、早退を「予定開始 + 9時間30分」で判定します。

### 管理区分(勤怠管理の対象を絞る)

従業員マスタの一番左にある **「管理区分」のチェック**(XML では `managed`)で、
勤怠管理の対象にする方を選べます。

- **チェックあり(既定)** … 突合結果の一覧にも帳票にも出ます
- **チェックなし** … シフト表・打刻データに載っていても**対象外**。一覧にも帳票にも出しません

マスタの編集画面(**従業員**タブ)も、既定ではチェックの付いた方だけを表示します。
外した方を戻すときは **「対象外も表示」** にチェックを入れてください。
`managed` を書いていない登録は対象(チェックあり)として扱うため、
これまでのマスタをそのまま使えます。

### 所定労働時間と休憩(`masters\working_hours.xml`)

早退・時間外の基準になる**予定終了時刻**は、次の式で決まります。

```
予定終了 = 予定開始 ＋ 所定労働時間 ＋ 休憩
```

**休憩は「所属部 × 期間 × 平日/土日祝」の3つ**で決まります。

| 書く場所 | 意味 |
|---|---|
| `<division>` の `weekdayBreak` / `holidayBreak` | その所属部の**既定**。期間で書いていない日に使う |
| `<period>` の `weekdayBreak` / `holidayBreak` | その**期間だけの上書き**。書かなければ所属部の既定を使う |

平日と土日祝が同じ場合は、どちらも `breakMinutes="90"` と1つ書けば両方に効きます。

```xml
<division name="業務部" weekdayBreak="90" holidayBreak="90">
  <period from="4/1" to="6/30" weekday="8"   holiday="8.5"/>                          <!-- 休憩は既定の90分 -->
  <period from="7/1" to="9/15" weekday="7.5" holiday="8" weekdayBreak="60" holidayBreak="45"/>
</division>
```

画面では **「マスタを編集」→「所定労働時間」** タブで編集します。
上の一覧が所属部の**既定の休憩**、下の一覧が**期間ごとの所定労働時間と休憩**で、
期間の休憩を空欄にすると既定の休憩を使います。
休憩が時期で変わらない所属部は、これまでどおり上の一覧だけ入れれば十分です。

### 申請書 確認一覧 (勤怠締め業務フロー STEP1 ④)

締めの業務フローでは、突合で差異が見つかると申請書を印刷して回付します。
その工程を支援するため、**判定結果から「どの申請書が、誰の、どの日の分で必要か」**を
一覧にして出力できます。

```powershell
.
un.ps1 -Cli run `
  "シフト表.xls" "7月修正" "打刻データ.xls" "出席記録" `
  --only-shift --forms-out "out\申請書確認一覧_202607.xlsx"
```

画面からは上部の **「申請書 確認一覧を出力」** ボタンで出力します。

| 判定 | 用意する申請書 |
|---|---|
| 有給 / 有給日に打刻 | 年次有休休暇・欠勤申請書 |
| その他(欠勤・特別休暇) | 年次有休休暇・欠勤申請書 |
| 終日出張 / 半日出張 | 出張届 |
| 打刻漏れ / 打刻3件以上 / シフトなし打刻 | タイムカード修正届出書 |
| 遅刻 / 早退 / 時間外30分 / 早出30分 / 公休に打刻 | 勤怠管理簿 |

- **判定が正常でも申請書が必要な日(有給・出張)を含めます。**
  仕様書 13.3「終日出張の日に申請書の提出済みを確認する」と同じ考え方です
- 対応づけは `masterspplication_form.xml` で変更できます。
  1つの判定コードに複数行を書くと、その日に必要な申請書が複数として出ます
- 申請書の様式は `TCC勤怠管理フォーマット最新（2026.4）.xls` と
  `【申請書】勤怠管理簿（7月）.xlsx` に収録されています

> **対応づけは業務フローから起こした案です。**
> 早出30分以上に申請書が要るか、公休に打刻がある日を「振替休日変更」とするかは
> 高根カントリー倶楽部様のご確認が必要です。

### 帳票の出力

**現在の提供範囲は、業務フローの STEP1「各部署締め」です。**

```
① シフト表        ┐
                  ├→ ③ 出席記録レポート ─ 差異あり → ④ 申請書を印刷
② タイムレコーダー ┘                                 ⑤ 出勤簿を作成
                                                    ⑥ パート給与計算表を作成
```

| 帳票 | フロー | 対象 | テンプレート |
|---|---|---|---|
| 出席記録レポート | ③ | 全対象者 | 必要(`--report`) |
| 申請書 確認一覧 | ④ | 差異のある日・申請の要る日 | 不要 |
| 出勤簿 | ⑤ | 全対象者 | 必要(`--book`) |
| パート・アルバイト給与計算表 | ⑥ | **パート・アルバイトのみ** | 必要(`--payroll`) |

テンプレート原本は複製して使い、原本は更新しません。

> **提供範囲外の帳票は `masters
eport_scope.xml` で隠しています。**
> 日別集計表(部門別) / 修正履歴一覧 / 打刻詳細一覧 は**実装済みですが表示していません**。
> 提供範囲を広げるときは、この設定の `show` を `true` にするだけです(作り直しは不要)。

```powershell
.\run.ps1 -Cli run `
  "シフト表.xls" "7月修正" "打刻データ.xls" "出席記録" --only-shift `
  --out-dir "out" `
  --book    "Materials\[提出]出勤簿.xls" `
  --payroll "Materials\[提出]パートアルバイト給与計算表.xlsx"
```

`--out-dir` を指定すると、帳票と一緒に**実行ログ**(`out\ログ\実行ログ_<実行ID>.txt`)も出力します。
入力ファイルのハッシュ・判定件数・修正履歴・出力先が入っており、締めの根拠として残せます。

**パート・アルバイト給与計算表**は1人1シートの様式で、このアプリが書き込むのは
出社時間・退社時間・**休憩時間**の3つだけです。丸め後の時刻・実働時間はテンプレート側の数式で求まります。
休憩は現在 手入力で運用されている欄で、そこを自動計算で埋めるのがこの帳票の要点です。

### 「氏名未解決」タブからの登録

一覧の行を選んで **「マスタに登録」**(行のダブルクリックでも可)を押すと、その氏名を
別名マスタへ登録するダイアログが開きます。

- **正式氏名の候補は打刻データの社員一覧から出します**(作業番号を持つため正式氏名として信頼できる)。
  **姓が一致する候補が先頭**に並び、1件だけなら最初から選ばれた状態で開きます
- 候補にない氏名は直接入力できます。空欄のまま登録すると「その表記自体が正式氏名」の登録になります
- 登録すると `masters\name_alias.xml` に書き込み、**続けて突合をやり直します**
  (帳票の編集セルがある場合は、破棄してよいか確認します)
- 同じ表記が既に登録されている場合は、行が増えずに正式氏名が書き換わります
  (空白の入り方だけが違う表記も同じ行として扱います)

### マスタの編集画面

上部の **「マスタを編集」** ボタン(「氏名未解決」タブにも同じボタンがあります)で、
3つのマスタを**Excel や XML エディタを開かずに画面で修正**できます。編集対象は突合で読み込むのと
同じ `masters\` フォルダのXMLです。

| タブ | 内容 | 入力 |
|---|---|---|
| 社員名 別名 | 「平山 部長」→「平山 恵亮」の対応(Blocker B-08) | 表記 / 正式氏名 / 備考 |
| 勤務区分 | 公・有・欠 などセルの文字値の意味 | 区分 / 種別(一覧から選択) / 備考 |
| 勤務パターン | 予定開始時刻に対する予定終了時刻(Blocker B-03) | 対象(正式氏名 または `*`) / 開始時刻 / 終了時刻 |

- **未解決の氏名を取り込む** — 直前の突合で「氏名未解決」だった氏名を別名マスタの行として追加します。
  正式氏名を入力して保存すれば、次の突合から自動で解決されます
  (正式氏名を空欄のままにした行は「その表記自体が正式氏名」の登録になります)
- **保存前に検査します** — 必須項目・重複・時刻の書式(`7:30`)を確かめ、誤りがあれば
  **1ファイルも書き換えずに**理由を表示します
- **説明コメントは残ります** — XMLに書かれているお客様向けの説明や、コメントアウトした候補行
  (「宮崎 プロ」など)はそのまま残し、対象の行だけを差し替えます
- **上書き前の控え** — 保存のたびに `name_alias.xml.bak` のように直前の内容を残します。
  手で編集した内容に戻したい場合はこのファイルを使ってください
- 一覧に無い開始時刻を「開始 + N時間」で補完する設定(`defaultWorkHours`)は、
  勤務パターンタブの **所定労働時間** 欄で設定します(空欄なら補完しません)

保存内容が突合結果に反映されるのは、次に**「突合実行」**を押したときからです。
勤務区分はセル編集ポップアップの選択肢にすぐ反映されます。

> **編集するのは実行ファイル配下の `masters\` です。**
> リポジトリ直下の `masters\` はビルド時にコピーされる元ファイルのため、画面での編集は反映されません。
> 配布物へ取り込む場合は、編集後のXMLをリポジトリ側にも反映してください。

## 6. 設計上の判断

| 論点 | 判断 | 理由 |
|---|---|---|
| レイアウトの特定方法 | 行・列を決め打ちせず「1,2,3… と連番が並ぶ行」を探して日付列を特定 | 月やシートで行位置がずれても動作させるため |
| シート選択 | 画面から選択(先頭シート固定にしない) | Blocker B-01/B-02(先頭シート運用)を運用変更なしで回避できる |
| 正式氏名の基準 | 打刻データ側の氏名を正式氏名として自動登録 | 作業番号を持ち一意性が高いため。空白の表記ゆれはマスタ不要で解決する |
| 帳票の社員一覧 | シフト表に載っている社員のみを、シフト表の記載順・記載どおりの部門で出力する | 締めの対象はシフト表に載っている社員のため。テンプレートは書式の雛形として使う |
| 部門の基準 | シフト表(競技課・営業課)を優先し、無ければ打刻データの部門 | 締めの単位がシフト表の部門のため。作業番号は打刻データにしかないので打刻側を採用する |
| 曖昧一致 | 行わない | 誤突合を防ぐため(詳細設計書 第7章) |
| 打刻の丸め | 帳票へは原文をそのまま出力し、丸めは勤務時間の算出にだけ使う | 出席記録レポートは実打刻をそのまま出力する要件のため。丸めた値は休憩・実労働の計算に使う (B-05) |
| 休憩時間 | 拘束時間(丸めた退勤−丸めた出勤)の帯で決める。帯・丸めは `break_rule.xml` で変更できる | お客様提示のルール (B-04)。運用が変わっても本体を直さずに合わせられるようにするため |
| 休憩の判定基準 | 実労働時間ではなく拘束時間で帯を選ぶ | 実労働で判定すると休憩を引いた結果で帯が変わり、計算が循環するため。提示いただいた例も拘束時間で一致する |
| 出退勤の採用 | 最初を出勤・最後を退勤(暫定) | Blocker B-09。1件のみの場合は「打刻が1件のみ」として要確認にする |
| 帳票の書き込み | テンプレートからは表題・期間欄・用紙設定・列幅のみ引き継ぎ、日番号行から下は毎回作り直す | テンプレートに残る書式のばらつき(塗り・斜線・不揃いな罫線)を出力に持ち込まないため |
| 帳票の画面編集 | 突合結果 → `ReportSheet` → Excel の一本道にし、画面は `ReportSheet` を直接編集する | 画面に見えているものと出力される帳票が食い違わないようにするため |
| 編集内容の保存 | `ReportSheet` を保留ファイル(`.kintai.json`)として保存し、そこから再開する | 締めの確認は一度で終わらないため。誰がいつ直したかの監査ログは別途必要(PoC では未対応) |
| 出力した .xlsx の読み戻し | 行わない | 現行様式では予定開始時刻を出力しないため、読み戻しても遅刻・早退・早出・時間外の判定根拠が復元できない。編集の器(`ReportSheet`)ごと保存する方式にした |
| 保留ファイルの形式 | JSON(日本語のまま・字下げ付き) | 中身をそのまま確認でき、形式の版数で将来の互換性を判断できるため |
